## Rollback boundary

The updater builds a fresh runtime at its permanent path, tests a separate source candidate and records a journal before modifying the application. Activation uses same-volume moves with persisted intent. Post-activation version/startup and desktop-shortcut checks must pass before commitment. Failures restore prior application files, runtime pointer, settings and shortcut; interrupted activation is repaired on the next update attempt. A failed rollback reports the backup path and retains its candidate runtime for recovery. Successful backups and old runtimes are retained.

This restores the application installation; it does not uninstall publisher-managed Python/Tesseract or remove downloaded language data. Screenshot/history/project/recovery files are outside application replacement. The CLI `-CloseRunningApp` option can discard unsaved work; save before invoking it. In-app updating first waits for recovery/PNG saves and locks editing.
